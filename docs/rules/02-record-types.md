# 記録の種類（面談／会議／見学）

> 生きた決まり（主題ファイル）。索引は台帳 `memo-okoshi-handoff.md` の「主題の索引」。書き足し方は CLAUDE.md「台帳の維持」。
> なぜそうしたか（経緯・実測）は `memo-okoshi-archive-2026-09.md`。ここには置かない。
> 2026-10-14 アーカイブ「いま守る制約（主題ごと移した節）」から移した（P24）。

- ⚠️ **記録の種類は3つ**: 面談（`interview`）・会議（`meeting`）・**見学（`visit`・P21）**。ホームのカードで選び、**変換の最後まで保つ**
  （`app/page.tsx` の `type`）。**辞書は共通**。API は `record_type` を受け取り、知らない値は面談として扱う。
- **項目ライブラリは種類ごとに別**（`ITEM_LIBRARY`＝面談・`MEETING_LIBRARY`＝会議・`libraryFor`）。
  **面談の項目・id・分類・既定は変えない**。会議は**4項目だけ**（会議概要／内容／決定事項／今後の対応）で追加項目を設けない。会議概要は記録の項目として残す。
  id は面談と重ねない。⚠️ **「今後の対応」の id は `shukudai` のまま**・**「宿題」の語を画面・プロンプト・出力に出さない**（`tests/meeting.test.mts`）。
- ⚠️ **赤は面談・会議とも働く**。会議も名前を塗って送り、塗った箇所は「〇〇」になって確認画面で人が書き入れる
  [DECISION 2026-09-23 P15・設計側]。⚠️ **P9 の「原則3は面談にのみ適用・会議は赤を持たない（`withoutRed`）」は無効**（`tests/red.test.mts`）。
- **会議のプロンプトは別関数**（`buildMeetingPrompt`）。**人名（赤）と塗りつぶしの規則は面談と共通の文**（`RED_RULE`・`MASK_RULE`）。
  会議: 内容・決定事項・今後の対応が混ざった走り書きを振り分ける／今後の対応は「担当：／期限：」で誰が・いつまでに・何を、
  **書かれていない要素は補わない**（担当未定・期限未定）／決定事項と検討事項を分ける／気づきは会議の観点
  （中身は `tests/meeting.test.mts`）／**会議名・日時・場所・出席者は用紙の頭の記入欄から必ず読み、会議概要に行を分けてまとめる**（空欄の行は書かない）。
- **見学は項目が決まっている**（`VISIT_LIBRARY`＝名前・日時・来所者・通園、通所先・住所・事前情報・内容の7つ・この順・コロン無し・1〜6 は1行の欄 `oneLine`）。
  **項目のオンオフ・並べ替え・追加項目・「その他」は無い**（`isFixedType`。確認画面の項目のドロワーと矢印も出さない）。赤・黄・青・こぼれ枠・気づきは同じに働く。
  **見学のプロンプトは別関数**（`buildVisitPrompt`・共通の `RED_RULE`・`MASK_RULE`）: 1〜6 は欄から・**空欄は空**・**日時は書かれたとおり**・
  名前・来所者・住所は塗られて〇〇の前提・入らない話は**まず内容へ**、それでも入らないものだけ spill（`tests/visit.test.mts`）[DECISION 2026-10-14 P21・設計側]。
- **項目の選択・並び・自由形式は種類ごとに別の鍵**（`keyFor`: 面談の鍵はそのまま、他は `:種類` を足す）。
- 出力の題は種類ごと（`outputTitle`: 会議記録／見学記録／面談・モニタリング記録）。転記・Word・PDF で共通。
